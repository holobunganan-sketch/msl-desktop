# 备份与恢复指南

## 数据放在哪里

| 内容 | 存放位置 | 是否备份 |
|---|---|---|
| 项目、事项、问答、报告、专家记录、记忆与设置 | `%APPDATA%\MSLDesktop\msl-desktop.db` | 是 |
| 专家上传资料的应用副本 | `%APPDATA%\MSLDesktop\attachments` | 是，仅包含仍被引用的资料 |
| 工作目录中的原始文件 | 用户绑定的外部目录 | 否，保留目录关联；请由原有文件备份方案保护 |
| 缓存、日志、临时数据 | `%LOCALAPPDATA%\MSLDesktop` | 否，可重新建立 |
| API Key | Windows 凭据管理器 | 否，更换电脑后重新填写 |
| 备份周期、目标路径与本机备份账本 | 用户数据目录中的 backup-settings.json / backup-state.json | 不跨设备恢复 |
| 多设备同步配置和本机同步状态 | 用户数据目录中的 sync-settings.json / sync-state.json | 否，各设备独立保存 |

应用不会因 Windows 数据路径缺失而把个人数据库创建在源码目录。正在使用的 SQLite 数据库始终留在本机 `%APPDATA%`。多设备协作通过“数据同步”交换已校验的记录和专家资料副本，云盘目录中不会放置正在运行的数据库文件。

## 多设备同步

1. 在第一台电脑的“设置 → 数据与备份 → 多设备数据同步”选择云盘客户端中的文件夹。空文件夹会创建 `MSLDesktop.sync/msl-workspace.json`，其他设备据此识别数据集。
2. 在另一台电脑选择同一云盘文件夹。检测到现有数据后，选择“使用文件夹中的数据”或“以本机数据建立新基线”。该选择决定首次连接起点，完成后进入双向同步。
3. 默认每 180 分钟运行一次，也可以调整为 5–10080 分钟或随时点击“立即同步”。应用关闭期间不会运行；下次启动达到周期后会补做。
4. 两台电脑修改不同事项或不同字段时会合并。同一字段存在离线并发修改时进入“需要选择的冲突”，由用户保留本机值或采用同步值；编辑时间与因果关系共同参与判断。
5. 工作目录路径、API Key、缓存和源工作文件保持在各自设备。专家资料的应用副本通过内容摘要校验后同步。
6. “同步完成”表示协议文件已经安全写入或读取本机云盘目录。云盘客户端是否完成网络上传，需要在对应客户端中核对。

## 第一次设置

1. 打开“设置 → 数据与备份”。
2. 选择一个独立文件夹，例如云盘客户端中的专用 MSL 备份目录。文件夹需要存在、已在本机可用且可写。应用不要求云服务账号或额外付费接口。
3. 保存设置，点击“立即备份”。等待“最近成功备份”出现时间及文件路径。
4. 若需要自动备份，开启开关并设定间隔与保留份数。默认间隔 1440 分钟、保留 7 份；开启后到期执行，应用关闭期间不会自动备份。
5. 确认云盘客户端已经完成上传。工作台显示的成功仅代表本地备份写入并校验成功。

目标目录不能与源码仓库、安装目录、应用数据、缓存或绑定的工作目录相互包含。网络断开或目标不可写时显示失败并保留已有备份。目录恢复可用后可以手动重试。

备份包为带版本清单和逐文件 SHA256 的 ZIP 容器，使用 `.mslbackup` 扩展名，默认未加密。请勿放入公开共享目录或上传 GitHub。保留策略只清理本安装记录的、归属一致且可校验的旧备份；不清理其他设备的备份或普通文件。手动备份和自动备份共用保留数量。

## 恢复或迁移电脑

1. 安装支持该备份版本的 MSL Desktop。
2. 在“数据与备份”选择来自可信来源的备份文件，点击“检查并预览恢复”。哈希校验用于检查包内一致性，不能证明备份来源可信。
3. 核对备份时间和版本。恢复会整体替换工作台记录，不执行多端记录合并。
4. 输入“恢复备份”，点击“确认并重启恢复”。恢复前副本会留在正式数据目录的 `.restore-标识/previous` 中。
5. 重启后核对记录与专家资料。自动分析、自动备份及同步保持关闭，自动目录监听不恢复；项目与目录关联保持原样，核对路径后再启用监控和分析。同步连接需要重新确认数据方向，避免旧备份自动写回现有同步目录。
6. 在其他电脑恢复时重新填写 API Key。已有电脑的 Windows 凭据保持原样。

恢复过程不修改或删除外部工作目录的原始文件。缓存不随备份搬运，后续按需重新索引。待确认建议仍需用户确认。中断的 AI 任务会标为中断，不自动重放。

若恢复时磁盘不足、包损坏、附件缺失、数据库版本过新或校验失败，恢复不会继续。启动阶段切换中断时优先还原旧数据库；如果旧数据库无法安全复位，应用会停止启动，保留恢复日志与回滚副本，避免生成一个空工作台掩盖故障。不要自行删除 `.restore-…/previous` 或恢复日志，请先保留整个数据目录用于处理。

## 推送 GitHub 前

运行 `pnpm check:publish`。检查器只读文件名，不读取密钥和数据正文，会检查已跟踪文件、未忽略的新文件以及本地可达提交历史。数据库、运行目录和 `.mslbackup` 由忽略规则保护。

此外，人工核对 README、其他文档、宣传图、示例 JSON、CSV 和日志中是否包含个人工作内容。使用虚构资料生成演示截图。忽略规则不能阻止 `git add -f`，也无法清除已经上传的提交；若发现历史误传，先停止推送，再制定针对性清理方案。
## WPS 云盘与上级 Git 仓库

WPS、OneDrive 等云盘的本地可访问文件夹可以用于备份和同步。若用户主目录本身是 Git 仓库，其下的云盘文件夹也会被 Git 覆盖。

遇到 Git 目录保护提示时，可点击“创建私有云盘子文件夹”。应用会在选定位置创建 `MSLDesktop-private`，并写入只包含 `*` 的 `.gitignore`，使该目录内的文件全部被 Git 忽略。已有被 Git 跟踪的内容仍会阻止启用；应用不会修改现有文件或上级 Git 配置，也不会替用户执行取消跟踪。

备份入口创建子目录后须保存备份设置；同步入口仍须确认首次数据方向。该校验需要本机 Git 可用。普通仓库外的云盘目录没有此依赖。请勿用强制添加、移除忽略文件或打包整个目录的方式上传私有数据；这项保护不提供加密功能。
