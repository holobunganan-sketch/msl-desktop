# 协作式工作流、节约请求与可读报告

基线：0.2.0，自然工作流代码及已安装程序；本轮按用户已授权的直接推进方式执行，不再次进行方案确认，不委派，不操作 Git 历史。

## 选择与边界

比较：全面自动写入会失去用户确认边界；降低模型能力、扫描频率或截断更多事实会影响颗粒度。本轮保留全部已有功能、当前扫描频率和模型路由，采用清晰的阶段提示、无损输入压缩、严格命中复用、结构化报告和同一事项的日历投影。

源工作目录只读；建议确认前不写正式实体；所有应用运行和写入测试隔离 APPDATA、LOCALAPPDATA、TEMP、TMP、WebView2，仅本地 Mock。新版本 0.2.1，本轮生成安装包，不因上一轮安装授权自动替换正式安装。

## 操作逻辑

主入口保留今天、项目、事项、日历、回顾。事项阶段保留待整理、待推进、等待中、已完成。每个阶段说明当前内容、秘书负责什么、用户下一步做什么。记录输入提供可选示例来降低启动成本，填写示例仅改变草稿，不自动保存或调用模型。状态回执准确区分“已保存，等待周期整理”和“已保存，后台整理中”。建议预览直接显示去向、所属项目、全部时间节点（包括独立截止和清除时间）、时间类型及日历结果；完整字段和原因保持可展开。

## 请求节约

1. 所有分析、项目整理、报告输入采用紧凑 JSON：只去除对象中的 null 字段，输入规范声明缺失可选字段等价于 null；保留全部非空事实、零值、false、空字符串、数组元素及覆盖范围。禁止压缩输出补丁的 null（它可表示用户要清除字段）。
2. 周期分析先按原逻辑扫描，构造事实快照。指纹保留当前日期、时间节点所处阶段、项目与细项状态、记录、文档内容指纹、记忆、覆盖缺口、模型连接配置和提示版本。只剔除窗口端点的时钟抖动、自身快照哈希。跨日、跨截止/跟进/预约节点、事实更新、配置或提示变化都使复用失效。
3. 已知输入截断或认知入口未完整覆盖时禁止复用；活动使用实际事件 ID 引用并明确超限标记。只复用最后一次成功的完整全局分析；聚焦事项、项目整理、失败、手动和重试不复用。沿用原成功批次建议，周期核查另记 reused 状态，不产生空的“最新建议”批次。SQLite 固定单行保存基线和累计输入字符/复用次数，不保留请求正文。
4. 展示累计减少的输入字符和复用次数；不把字符计数当作真实 token 或账单。保留覆盖缺口说明，不声称超出原输入范围的完整理解。

## 周报与月报

周报为序号列表，按照成果、项目进展、独立事项、阻碍、下期重点组织有内容的条目，避免强行补齐空类别。每条围绕具体主题呈现“变化/结果 → 影响 → 下一步”，有项目时展示真实项目名称。月报允许更多条目与更深的趋势分析，融合上月工作台变动和重叠周报，区分周报覆盖区间。

后台采用版本化 report-spec、结构化 JSON 输出、证据引用验证、文本长度/技术字段/置信分类验证、确定性人类可读渲染。最多一次格式或契约修复；修复失败保留失败状态，不用编号包装错误文本。文档变更仅能证明资料变化，不能直接当作业务完成。历史任务快照和周期内变化分开，周期后发生的状态不得声称在周期内完成。所有来源引用只在验证/元数据使用，正文无 entity_id 等内部标记。不请求或保存模型思维链。

报告页面以正文为主，设置与自定义周期折叠，保留历史清理和背景生成。提供复制可读正文。空范围可明确说明资料不足，不编造工作成果。

## 时间安排与日历

任务预约、任务截止、等待跟进和独立日程统一投影到日历。每个投影携带原实体 ID 和时间类型，点击直达原事项；改期、完成、撤销实时反映，不创建复制实体。任务同时有预约和截止时，两种不同时间节点各自保留；同一时间仅显示预约以去重。无具体时刻的日期以日期提醒呈现，不误称已预约。

AI 可建议时间，payload 的 time_basis 为 explicit 或 inferred；inferred 必须给出 time_reason。时间必须通过类型、正数、开始结束顺序校验。建议采用后才生效，推算时间标注“建议时间，采用后进入日历”。提示规范要求避开已知预约冲突、尊重截止日、无法合理安排则提一个澄清问题。程序不保证语义级排期完全正确，用户确认承担最终选择，测试覆盖其确认边界与投影身份。

## 验收

前端检查/构建、Node 行为测试、Rust fmt/test、隔离 Mock、复用请求计数与失效、报告坏输出/引用/修复、确认前后日历/撤销、重启持久化、只读/缓存回归、数据库备份副本迁移、release/NSIS。中英文、双尺寸、大字号截图验证，最终视觉认可前状态最多 PARTIALLY_COMPLETED。真实 AI 文风与远端可用性不由 Mock 验收替代。
