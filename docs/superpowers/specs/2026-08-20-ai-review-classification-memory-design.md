# AI 审阅与分类记忆设计

## 目标

- 修复建议标题存放在卡片字段、确认逻辑却只读取 `payload.title` 导致的写入失败。
- 让工作、任务、等待事项、日历、收件箱和工作续接点使用适合各自类型的可读编辑表单。
- 通过确认、改分类后确认和拒绝三种明确操作积累本地分类反馈，并让后续综合分析调用相关规律。

## 确认写入规则

卡片标题是统一标题来源。确认前，后端把它规范化写入 Work、Task、Waiting、Calendar 的 `payload.title`；Inbox 使用 `payload.content`。已有实体的更新会保留模型没有涉及的字段。确认事务同时写入业务实体、建议状态、活动记录和分类反馈，任一步骤失败都会回滚。

## 本地分类记忆

实现采用 Mem0 与 LangMem 常见的反馈记忆生命周期：记录、合并、召回、注入。

1. 记录：确认且分类未变记为 `accepted`；分类或 Work 归属发生调整后确认记为 `corrected`；拒绝记为 `rejected`。
2. 合并：以标题规范化结果、原建议类型和来源类型生成指纹；重复反馈合并计数，控制长期体积。
3. 召回：按反馈强度和最近更新时间选择最多 24 条规律。
4. 注入：规律进入综合分析快照。系统提示词要求模型把已接受或已纠正分类视为强偏好，把拒绝视为负向证据，并以当前信息为最终判断依据。

记忆保存在 SQLite 的 `classification_memories`，不需要外部服务、额外凭据或向量数据库。表内仅保留建议标题、类型、Work 归属、来源类型和字段名，不复制工作文件正文。缓存清理把该表列为受保护数据。

## 审阅界面

主编辑区按目标类型显示业务字段。完整 JSON 放入默认收起的“高级字段”，供异常修正和审计使用。错误提示位于分析状态卡片内部，避免遮挡状态与批次筛选。状态卡显示已积累的反馈数量，让用户知道分类记忆是否正在学习。
