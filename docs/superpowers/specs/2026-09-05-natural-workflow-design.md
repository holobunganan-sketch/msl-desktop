# 自然工作流交互重构

用户于本轮明确批准此前对话设计并要求直接重构。执行地点为现有脏工作树，不创建分支或提交，不委派。

## 目标与边界

日常操作为「记一下 → 看建议 → 继续做」。主要导航为今天、项目、事项、日历、回顾；工具入口保留翻译、目录与设置。事项提供待整理、待推进、等待中、已完成视图，待整理包含原始记录与待确认建议，两者分开呈现，避免误认成重复记录。

保留 SQLite 正式实体与现有确认、撤销、分类记忆、后台任务服务。AI 建议确认前只写队列。工作目录只读。全部运行与写入测试隔离 APPDATA、LOCALAPPDATA、TEMP、TMP 和 WebView2 目录，仅本地 Mock AI。禁止读取或调用真实凭据。

## 交互契约

1. 全局记录可直接保存，可选择立即交秘书整理；当前项目自动作为记录上下文。记录提交具有防重复锁，失败保留输入，保存成功后即使 AI 失败原始记录仍存在。
2. 首页顶部紧凑工作判断和可展开简报；继续推进与需要您决定占主要区域；其余信息降为可展开辅助区。卡片不嵌套固定高度滚动，长文本和大字号可自然扩展。
3. 建议默认呈现标题、建议动作、归属、时间、必要说明，操作为采用安排、调整、稍后。调整展示现有完整编辑器。稍后不产生错误分类反馈。完整审阅保留最近7天记录与更早待处理项，筛选和技术信息按需展开。
4. 项目先展示目标、现状、下一步、阻塞；主操作为记进展、加一件事、让秘书整理。资料与历史按需展开。自然语言进展先进入队列。
5. 跳转携带实体ID，目标页面直接定位具体条目。首页、搜索、确认回执和项目子项共用导航契约。显示明确去向与撤销结果。
6. 已安排的任务使用任务本身的 scheduled_start/end 字段展示在日历，改期保留相同任务ID、项目和历史，不复制日历实体。日期不明确不擅自猜测。
7. 项目上下文通过结构化记录字段交给 AI；提示规范要求区分已完成动作与新等待事项，避免重新创建已有任务或长期项目。

## 验收

新用户可完成记录、查看建议、采用或调整到具体项目、找到目标、安排时间、标记完成、补充进展和撤销。中文/英文、1100×720/1440×1000、大字号、长标题与空状态均可用。执行前端检查与构建、Node 行为测试、Rust 格式和测试、隔离 CDP Mock 流程与持久化、缓存/只读边界回归及 release 构建。截图审阅前状态最高 PARTIALLY_COMPLETED。
