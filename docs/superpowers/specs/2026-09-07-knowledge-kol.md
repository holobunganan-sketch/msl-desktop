# 全局问答与专家洞察 — 已确认设计

用户已在当前对话确认范围并授权实施、验证后自动卸载旧版安装新版。版本目标 0.3.0。无需再次讨论产品方向。

## 工作台问答
- 独立入口，全局查询项目、任务、等待、日历、收件箱、进展、活动、目录索引/正文、建议/决定、简报/报告和 KOL 数据。
- @ 选择真实项目 ID，多选、清除、同名区分；每轮持久化范围，追问继承，切换范围不混入其他项目的聊天上下文。
- SQL 仅使用程序白名单查询。凭据、配置、缓存管理信息不作为知识。项目范围在检索前强制执行，未知/已删除项目明确报错，不能静默扩大到全局。
- 先定位记录，再选择片段；覆盖计数、遗漏、不可读/过期文件明确展示。统计由程序计算，不能把取样数当总体数。
- 回答契约区分事实与推断；每项带真实证据 ID 和逐字引用，未知来源/伪造引用拒绝并最多一次校正。引用通过不等于医学真实性已验证，UI 保留限制说明。
- 历史会话可恢复，回答只用于理解上下文，不能自我引用作为新事实；问题/范围/来源快照/回答保存在 SQLite，不受缓存清理影响。
- 后台任务切页继续，重复发起同轮不重复执行，失败可重试，退出后中断可见。问答只读，转安排须进入现有确认流程。

## KOL · 专家与洞察
- 独立左侧入口：待跟进、专家、洞察。基础档案仅姓名和机构/科室为最小识别信息，不建立关系/处方评分。
- 自由文本记交流，保留原话、日期、专家、可选项目和原收件箱来源；明确专家身份，不按同名自动合并。
- 专家可关联多个项目；交流可独立。任务/等待/日历为同一工作台实体，不维护复制待办。
- AI 按临床实践障碍、证据需求、研究合作机会三类分析，可交叉分类。提供摘要、线索、依据、不确定项、验证问题及下一步动作。
- AI 输出为可编辑草稿。确认时在一个事务中保存审阅后的洞察及选中的正式事项，允许取消单条动作或改类型、项目、时间。幂等确认防重复；原话始终保留。
- 洞察状态为待验证、已审阅、已修正/不成立；用户审阅表示工作判断，不能标记医学结论已证实。按原始来源去重，展示独立专家数、记录数和日期。
- 会前准备可按专家的近期原话、现有洞察、待跟进事项生成有来源的结果，不产生承诺。
- 默认中文，支持英文；字号与配色沿用现有设置，双尺寸大字号下不裁切，动作可滚动到达。

## 不可越界
- 不读真实 API Key、不调用真实 Provider 做测试；所有运行/写入测试隔离 APPDATA、LOCALAPPDATA、TEMP、TMP、WebView2。
- 真实工作目录源文件只读；数据迁移先在现有正式备份的独立副本测试。
- 保留全部脏工作树；不执行 reset/checkout/clean/stash/rebase/commit，不委派子代理。
- 新表与新来源不受缓存清理误删；全部机械验证和 release 构建通过后才可部署。正式替换先冷备份，卸载保留数据，安装后只启动隔离测试实例。
