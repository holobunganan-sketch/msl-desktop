# 项目流转与后台 AI — 2026-09-05

本轮范围：修复 AI JSON 错误、项目关联文件夹、收件箱转项目细项、项目级 AI 整理、结构化行动规范、后台任务与 SQLite 持久化。

## 实现

1. **AI 输出处理**：区分 JSON 语法和字段结构错误；接受带说明文字/代码围栏的单个完整 JSON 对象；拒绝残缺对象、多个对象、越权操作及伪造来源。首次验证失败后，由同一已选择模型进行一次格式校正；再次失败时保留明确错误，整批建议不落库。
2. **结构化行动规范**：`src-tauri/src/ai/secretary-spec.md` 随应用编译加载，全局分析和项目整理共用。定义读取顺序、项目语义、细项字段、证据、更新目标、缺失信息处理、确认边界。模型输出仍须通过程序验证。
3. **项目文件夹**：在项目详情选择文件夹或关联已有工作目录，支持多个目录；重复关联幂等；解除关联保留源文件。新增项目目录不替换工作台主监听目录。分析前在独立后台连接刷新目录索引。
4. **项目整理**：项目内的任务（含未来/完成项）、等待、日程、进度历史和关联目录资料进入项目范围快照；尚未关联文件夹的项目也可整理已有事项。细项与项目绑定，跨项目更新被拒绝。每类细项最多 300 条，文件正文沿用既有数量/字符预算，遗漏信息有截断计数。
5. **收件箱归入项目**：选择项目，再选择任务、等待、日程或进度记录。保留原始记录及转换目标，重复转换被阻止；转换在事务中完成。进度记录继承原下一步及提醒。
6. **后台任务**：Rust 侧独立执行，SQLite 保存运行状态、结果或错误。前端页面切换和 WebView 重载不取消任务；侧边栏“后台任务”提供统一入口和完成提醒。简报、全局/项目分析、周月报、翻译及对应重试接入同一机制，定时任务也使用该入口。
7. **存储**：沿用原 SQLite 数据库、WAL、外键和 busy timeout，追加 0009 迁移及任务/等待/收件箱索引。最多 4 个并发后台任务，相同在途请求复用。已结束执行回执在后续任务发起时按 7 天及约 200 条上限回收；正式项目、建议、保留简报和报告保持独立存储。

## 使用边界

- 关闭窗口后常驻内核可继续运行；真正退出应用会中断未完成任务，下次启动明确标记中断，可重新发起。
- 未承诺应用完全退出后仍执行网络调用，也不会自动重新提交中断请求。
- AI 建议必须经过人工确认才能写入正式实体。模型校正请求会产生最多一次额外模型调用。
- API Key 仍由系统凭据管理器保存；本轮测试仅使用合成凭据和本地 Mock Provider。
- 测试 APPDATA、LOCALAPPDATA、TEMP、TMP 均隔离；测试目录资料为合成内容。正式数据库仅复制后迁移验证，没有用于启动测试实例。
