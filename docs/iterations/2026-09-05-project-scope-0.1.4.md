# 项目归属与审阅状态修复 · 0.1.4

## 本轮范围

用户截图中的 `status 值无效`，以及长期项目和独立事项之间的归属规则。
保留既有成果，无 Git 回退、清理或提交；没有更改源工作目录中的文件。

## 根因与修复

- 只读检查发现旧版已编辑建议存在 `kind=work`、`status=next` 的组合。旧编辑器切换类型时保留了任务状态，后端在确认时拒绝此组合。
- 类型切换统一转换目标字段，保留当前编辑内容。已保存的旧建议仅在状态明确属于原类型时调整；未知状态仍要求用户选择，避免猜测。
- 长期项目、任务、等待各有状态选择框。空状态表示保持原状态或使用新建默认值。
- 生成校验、草稿保存和确认共用状态验证。无效模型输出进入已有的一次格式修复流程，修复失败时不写正式实体。
- 草稿和确认校验具体项目是否存在、是否归档。项目进展必须选择已有项目。
- 批量确认先保存所有勾选卡片的修改，再执行原子确认。卡片切换后的归属修改也会生效。

## 产品规则

1. **工作**：长期跟进项目。新建项目与归入已有项目有不同入口。
2. **任务、等待、日历**：可以归入指定项目，也可以选择“独立事项（不归属项目）”。列表展示归属，可按项目或独立事项筛选。
3. **收件箱**：待整理入口。归入已有项目时选择项目以及任务、等待、日程或进展记录；保留直接转成独立事项的路径。
4. **AI 审阅和首页决策卡**：使用相同的归属组件；加入已有项目不会因此新建或重命名项目。
5. **项目详情**：汇总所属任务、等待、日程和进展。现有 SQLite 可空 `work_id` 已支持这些关系，本轮无需新增数据库迁移。
6. **AI 约束**：提示词和 action spec 升级到 v4。明确要求项目身份、归属理由、有效状态、真实 ID，更新时保留未变字段，未经确认不得落入正式事项。
7. **源文件**：只读边界不变。管理和归属变更只作用于工作台记录。
