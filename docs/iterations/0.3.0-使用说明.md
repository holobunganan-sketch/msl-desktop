# MSL Desktop 0.3.0：问答与专家洞察

## 工作台问答

左侧进入“工作台问答”，直接输入问题。默认查询全部工作台信息。

输入 @，选择一个或多个项目。选中的项目会显示为标签；后续追问沿用当前范围。点标签上的 × 移除项目，或点“恢复全局”。也可从项目详情点“问这个项目”。

回答分为记录依据、分析推断和资料缺口。展开“依据”可核对引用片段；展开“本轮检索范围”可查看数据截至时间和未纳入的记录。回答本身不会修改任务、日历或源文件。

对话保存在本机 SQLite 中，可以稍后继续。切换页面时分析继续；完全退出软件会中断未完成的分析，重新打开后可以重试。删除对话不会删除项目记录。

### 如何获得更准确的回答

尽量说明时间段和想解决的问题，例如：“@免疫知识补齐 最近两周有哪些进展？下周我需要跟进谁？”

模型会选取相关记录和文件片段，并非逐次通读所有文件。取样、不可读文件和资料缺口会披露。旧版跨项目周报尚无可靠的分段项目标签，在单项目范围中不会混入全文；可切回全局查阅。

引用可以核对来源，不能保证每个推断都正确。涉及医学结论时仍需核对原始证据。

## 专家与洞察

1. 添加专家：填写姓名与机构/科室即可，关注领域和项目关联可以稍后补充。同名专家分别保存。
2. 记交流：随手写下专家的观点、问题或需要跟进的承诺，也可以带入收件箱已有记录。
3. 点击“保存并让 AI 整理”：原话先保存，后台生成可编辑草稿。
4. 审阅草稿：核对三类洞察——临床实践障碍、证据需求、研究合作机会。三类可以交叉；不确定性和下一次追问单独展示。
5. 选择后续动作：修改事项、去向、项目和时间，取消不需要的动作，再确认写入。

有时间的任务与等待事项会沿用原记录进入日历；明确预约可选择“日历”。AI 推算的时间会标明依据，确认前可调整。跟进页读取同一条工作台记录，完成状态同步变化。

“准备下次交流”用于回顾原话、未完成承诺和问题，不创建新的承诺。“跨专家寻找共性”可生成有出处的共性洞察；同一专家的重复表达不会被标成独立专家共识。已确认洞察仍可补充判断、修正或标记为暂不支持。

## 模型与数据

设置中的任务模型分配新增“全局 / 项目连续问答”和“专家交流与洞察”。可以分别选择已配置的模型；未建立专用路由时沿用已配置的通用路由。若提示未配置路由，请在这里选择模型。

API Key 仍使用现有凭据机制。项目目录源文件保持只读。缓存清理不会移除对话、交流原话、草稿、已确认洞察或正式事项。
