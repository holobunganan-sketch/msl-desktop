# 多设备同步数据范围

## 基本边界

- 每台设备使用 `%APPDATA%\MSLDesktop\msl-desktop.db`，运行中的数据库不进入云盘目录。
- 云盘文件夹只保存 `MSLDesktop.sync` 协议目录、不可覆盖的设备状态和按摘要命名的专家资料副本。
- API Key、供应商启停、模型路由、本机绝对路径、缓存、日志、临时文件和源工作文件保持本机状态。
- 工作目录在各设备分别绑定。同步不会创建、修改、移动或删除工作目录中的文件。

## 当前同步的正式数据

| 数据 | 关系处理 | 说明 |
| --- | --- | --- |
| 长期项目、任务、等待事项、日历、收件箱、推进记录 | 全局实体 ID 映射 | 两机整数主键碰撞时重新分配本机主键，项目关系随映射恢复 |
| 工作活动 | 项目关系映射 | 本机目录 ID、绝对路径和可能包含路径的元数据不交换 |
| 分析运行、每日简报、建议、审阅决定、分类记忆 | 已登记外键及结构化目标映射 | 本机模型 ID、工作目录 ID不交换 |
| 周报与月报 | 内容和周期同步 | 本机模型 ID不交换 |
| 连续问答会话与回答 | 会话、项目范围、证据及规范化展示文档映射 | 只改写已登记的结构化标识，原文摘录保持原样 |
| 专家、交流、草稿、洞察与跟进建议 | 专家、项目、收件箱和草稿关系映射 | 专家与多个项目的关联共同同步，机构与科室保持独立字段 |
| 专家资料、提取片段 | 专家、资料、内容摘要关系映射 | 文件副本按 SHA-256 校验；缺损或摘要不符会停止导入 |
| 收件箱归属上下文 | 收件箱与项目标识映射 | 保留后续整理的项目范围 |

## 本机数据与可重建数据

| 类别 | 示例 | 原因 |
| --- | --- | --- |
| 本机配置 | 供应商、模型、API Key 引用、任务路由、窗口状态、同步周期和路径 | 设备能力、凭据和路径不同 |
| 本机目录投影 | workspaces、目录监听状态、文件绝对路径、工作目录绑定 | 同一项目在两台电脑上的路径可能不同 |
| 可重建索引 | document_index、FTS、cache_entries、认知缓存、清理日志 | 可从正式记录或受支持文件重新生成 |
| 运行状态 | 后台任务锁、调度水位、临时错误输出 | 不应跨设备接管正在执行的任务 |
| 本机操作回执 | proposal_receipts 中的撤销快照 | 已确认结果同步；跨设备撤销旧操作未开放，避免使用另一设备的整数 ID 回滚 |

## 合并与冲突

- 已登记实体拥有跨设备稳定标识。数据库事务同时记录原始编辑时间和字段变化，事务回滚时不留下已提交编辑。
- 收取远端数据前先捕获本机尚未发布的修改。字段因果关系优先于设备时钟；离线并发修改保留冲突。
- 不同字段的编辑可以合并；同一字段存在竞争时保留两个候选并进入冲突列表。
- 删除作为同步状态传播。遇到删除与离线编辑竞争时保留冲突，避免静默恢复或静默丢弃。
- 用户解决冲突会生成新的本机字段版本，并在下一次同步传播。
- 各设备状态文件使用设备 ID、序号和内容摘要联合去重，重复到达不会重复写入。同一设备序号出现不同内容会停止导入。

## 文件完整性与保留策略

- 当前写入协议版本为 2；可读取版本 1。较旧应用遇到新协议应先升级，不能混用不支持的协议。
- 接收时核对应用、数据集、代次、设备、序号及 SHA-256。拒绝目录穿越、链接跳转、缺失分块和损坏内容。
- 大状态按记录分块传输，全部验证后在单一数据库事务中应用。单记录最大 8 MiB、单快照最大 128 MiB；超限明确报错，不截断正式记录。
- 无变化时复用检查点。每台设备在当前代次保留最近 8 个已验证的完整检查点；只清理能够确认归属的旧文件及无剩余引用的对应分块。
- 删除标记持续保留以保护长期离线设备。未知云盘冲突副本、中断留下的孤立分块、旧代次及本机元数据不会盲目清理，存储量仍需监测。

## 使用边界

- 同步成功表示本机同步目录读写完成，不能证明云盘网络传输已经完成。
- 首次选择文件夹数据前保存恢复副本，然后切换业务数据基线；原始工作文件及凭据不变。
- 恢复备份后暂停同步并清除连接基线，需要重新确认数据方向。
- 自动分析按本机收到的主设备标识调度。云盘离线或传播滞后期间不具备跨设备强一致锁，切换主设备前应先暂停原设备自动分析并等待云盘传输完成。
- 协议摘要提供完整性校验，不提供身份认证或加密；同步文件夹应由可信设备独占使用。
